# Getting the mobile app onto GitHub

The backend monorepo (`C:\dev\cleanbnb\darclean`) is already on GitHub at
`moadelha/darclean` and needs nothing here — its `.gitignore` is fine and
nothing unwanted is tracked.

**This app is the one that isn't.** `C:\Users\elhan\darclean-mobile\darclean-mobile`
is its own git repo, but it has **no remote**, one commit from August
(`d72a984 darclean_v00`), and **58 changed files** on top of it — every part
from 1 through 41 is sitting uncommitted on your disk only. If this machine
dies, all of it is gone.

---

## 1. Check what you're about to commit

`.gitignore` has been rewritten (see the end of this file for what changed).
Confirm it's doing its job before anything else:

```powershell
cd C:\Users\elhan\darclean-mobile\darclean-mobile
git status --short
```

You should see roughly 58 entries and **no** `node_modules/`, no `.env`, no
`_to_delete/`. If `node_modules` appears, stop — the ignore file isn't being
picked up, and committing it would push tens of thousands of files.

Double-check the two that matter most:

```powershell
git check-ignore -v .env node_modules _to_delete
```

Each should print the `.gitignore` rule that catches it. Silence means it is
**not** ignored.

## 2. Commit the work

```powershell
git add -A
git commit -m "Host app: redesign, check-in workflow, calendar, notifications (Parts 1-41)"
```

`git add -A` is safe here *because* step 1 confirmed the ignore rules work —
it stages deletions too, which matters since several old tab files were
removed during the nav restructures.

## 3. Rename the branch

The repo is on `master`; GitHub and your other repo both use `main`. Worth
matching now rather than living with two conventions:

```powershell
git branch -M main
```

## 4. Create the GitHub repo

On github.com → **New repository**:

- Name: `readydar-mobile` (or `darclean-mobile` to match the folder)
- **Private** — recommended. Nothing secret is tracked, but the repo does
  reveal your API URL, EAS project id and full app structure.
- **Do not** tick "Add a README", "Add .gitignore" or "Choose a license".
  Any of those creates a first commit, and your push will then be rejected
  as unrelated history.

## 5. Connect and push

Copy the HTTPS URL GitHub shows you, then:

```powershell
git remote add origin https://github.com/moadelha/readydar-mobile.git
git push -u origin main
```

`-u` sets the upstream, so from then on plain `git push` and `git pull` work
with no arguments.

If it asks for a password: GitHub stopped accepting account passwords over
HTTPS. Use a **personal access token** (github.com → Settings → Developer
settings → Personal access tokens → Fine-grained tokens, with Contents:
Read and write on this repo) as the password, or install GitHub CLI and run
`gh auth login` once.

---

## Day-to-day from then on

```powershell
git add -A
git commit -m "what changed"
git push
```

Worth doing **before** each `eas build` or `eas update`, so every version
that reaches a phone has a commit you can go back to.

## What changed in `.gitignore`

The old one already covered `node_modules/`, `.expo/`, `dist/`,
`web-build/`, `.env`, signing keys and logs. Added:

| added | why |
|---|---|
| `_to_delete/` | Old tab files moved aside during the nav restructures (Parts 5, 12, 31). Scratch, not source — and safe to delete outright once the app is confirmed working. |
| `/android/`, `/ios/` | Generated by `expo prebuild` from `app.json`. Committing them creates a second source of truth for the same native config. |
| `*.apk`, `*.aab`, `*.ipa` | A build is ~60MB and git keeps every version forever. Download them from the EAS dashboard instead. |
| `*.keystore`, `credentials.json` | The old file caught `*.jks` but not these. A signing key in a repo lets anyone ship an update signed as your app. |
| `.env.local`, `.env.*.local`, `!.env.example` | Local overrides ignored; the placeholder file stays tracked so a fresh clone knows which variables to set. |
| `.expo-shared/`, `*.tsbuildinfo`, `.vscode/`, `.idea/`, `Thumbs.db` | Editor and tooling noise. |

`.env` was already ignored and `.env.example` already tracked — that part was
right, and it's worth keeping that way: `.env` holds your real API URL,
`.env.example` holds placeholders.
